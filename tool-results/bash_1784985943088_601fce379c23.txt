## 10. Notable Bugs / Issues (Audit Findings)

These come from `c.md` (an external TurboCore audit dated July 5 2026) cross-referenced with what I read in the code:

### Critical
1. **`middleware.ts` → `proxy.ts` rename for Next.js 16** — `c.md` flagged that the original `src/middleware.ts` was not being picked up by Next.js 16 (which expects `proxy.ts` with an exported `proxy` function). **Verified fixed**: `src/proxy.ts` exists with `export default function proxy(req: NextRequest)` and exports the proper config. CSRF, IP block/allow list, maintenance mode, and admin edge rate limit all run from `proxy.ts` now.

### High (build-blockers — `c.md` flagged 4)
2. **Investment liquidation import bug** — `c.md` said `/api/investments/[id]/liquidate/route.ts` imported a non-existent `liquidate` function. **Verified pattern**: the route exists; the liquidate logic is now a method on the `investments` singleton (`investments.liquidate(user.id, id)`). Could not confirm the import is correct without reading that specific route file, but the pattern is in place.
3. **`/api/v1/intl/quote` dropped `sourceAmountMinor`** — `c.md` said the route referenced a non-existent field on `FxQuoteResult`. The `FxQuote` interface in `providers/interfaces.ts` does only have `destinationAmountMinor`. Audit recommended using the parsed request value — status unverified.
4. **Card freeze/unfreeze/terminate/create imported from non-existent `virtualCards`** — `c.md` said `card.service.ts` imported `virtualCards` from `@/lib/turbocore/virtual-cards` (which has no `index.ts`, only `enhanced.ts`). The audit recommended replacing with `enhancedCards`. **Verified**: `enhanced.ts` is the only file in that directory; the export `enhancedCards` exists. Could not confirm `card.service.ts` is fully migrated without reading it, but the fix path is clear.
5. **Admin circuit-breaker `getState()` was private** — `c.md` said `listCircuitBreakers()` called `breaker.getState()` which was `private`. Recommended dropping the modifier. Status unverified.

### High (security)
6. **Cron secret fallback gap** — `c.md` flagged that `/api/cron/data-retention/route.ts` used `process.env.CRON_SECRET ?? "dev-cron-secret"` without the production guard. The other 12 cron routes use the proper `?? (process.env.NODE_ENV === "production" ? null : "dev-cron-secret")` pattern. **Spot-checked**: `cron-auth.ts` exists with `verifyCronSecret()` helper that handles this. Status: likely still inconsistent or now centralized.
7. **Referral rewards tagged as `"FUNDING"`** — `c.md` flagged that referral rewards were tagged as `Transaction.type: "FUNDING"`, indistinguishable from genuine deposits in AML/reconciliation. Recommended `"REFERRAL_REWARD"`. **Verified**: `RefType` now includes `"REFERRAL_REWARD"` (in `types.ts`), and `referrals/index.ts` calls `creditWallet(wallet.id, referral.rewardKobo, "REFERRAL_REWARD", …)`. **Fixed.**

### Medium
8. **SSRF guard checks hostnames, not resolved IPs** — `ssrf.ts` blocks literal private IPs + hostname blocklist but doesn't `dns.lookup()` before connecting. DNS-rebinding bypass possible. Admin-gated only (provider `baseUrl` / health-check URLs settable only via admin routes). Audit recommended resolving + pinning IP via custom `lookup` function. Status: unverified.
9. **No sanctions/watchlist screening found** — `c.md` searched broadly for sanctions/OFAC/PEP and found only `compliance/cases.ts` (case workflow, not screening). Models `SanctionsEntry` + `ScreeningResult` exist in Prisma schema now, and admin route `/api/admin/sanctions/screen` exists. Status: appears added but possibly still stub-level.
10. **Routing engine weights are hardcoded** — `routing-engine.ts` has `DEFAULT_WEIGHTS`/`FX_WEIGHTS` as in-code constants. Changing routing priorities requires code change + redeploy. Not a bug but a limitation.

### Low / code quality (from `c.md` + `IMPROVEMENT_PLAN.md`)

## Next Actions (for recreating this in a fresh Next.js project)

1. **Decide scope**: The Turbopay codebase is enormous (83 models, ~340 API routes, 52 views). For a clean Next.js recreation, pick a subset (e.g. MVP: auth + wallet + transfer + airtime + bills + history + KYC + admin overview).
2. **Adopt the architecture**: Next.js 16 App Router + Prisma + PostgreSQL + Redis + Tailwind 4 + shadcn/ui + Zustand + custom SWR client. Same as Turbopay.
3. **Skip the deprecated `src/` SDK and `frontend/` mock dashboard** entirely.
4. **Reuse the brand system**: Deep Emerald primary + Amber accent, Geist fonts, dark mode default, RTL support, signature wallet card gradient.
5. **Reuse the data model**: The Prisma schema is the most valuable artifact. Port the 20-30 most important models (User, Session, Wallet, LedgerEntry, Transaction, VirtualAccount, IdempotencyRecord, AuditLog, AmlFlag, Beneficiary, BillPayment, AirtimeDataPurchase, OtpCode, KycVerification, etc.).
